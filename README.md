# mix_precompiled_deps

Run `mix` directly against dependencies that are already compiled, such as
Hex packages built by Nix and sitting in the Nix store.

> [!IMPORTANT]
> Requires an Elixir with three small Mix patches, shipped in
> [`patches/`](patches/). On a stock Elixir, Mix will try to recompile the
> store paths and fail.

## Why

Nix can build each Hex dependency once and cache it like any other package
(nixpkgs' `buildMix`/`buildRebar3`, generated by
[deps_nix](https://github.com/code-supply/deps_nix)). But Mix insists on
owning `deps/` and `_build/`, so actually *using* those builds means either
recompiling every dependency in every derivation, or copying them into
`_build` and faking Mix's metadata.

This package is a `Mix.SCM` that tells Mix where the prebuilt dependencies
already are. Then `mix test`, `mix credo`, `mix dialyzer`, `mix format`, and
so on just work, in a Nix sandbox or a dev shell:

- no `mix deps.get`, no Hex, no network
- no dependency compilation, only your own code
- `mix test` and friends become cheap flake checks
- a dialyzer PLT built against store paths is valid on every machine

## How it works

1. **Nix builds each dependency.** `buildMix` already produces the source
   (`$out/src`) and the compiled app (`$out/lib/erlang/lib/<name>-<vsn>`).
2. **Nix writes a manifest**, an `.exs` file mapping each dependency to
   those two paths, plus a hash of the `mix.lock` it came from.
3. **`MIX_PRECOMPILED_DEPS` points at the manifest.** A hook in your
   `mix.exs` registers the SCM, and Mix loads every dependency from the
   store without compiling, cleaning, or writing to it.

With the variable unset, nothing changes: `mix deps.get` and normal Hex
workflows behave as usual.

## Usage

A complete, runnable version of this is in
[`examples/hello`](examples/hello) (`nix build .#checks.x86_64-linux.example-hello`).

**`mix.exs`**: install the hook. It's a no-op when the package isn't loaded:

```elixir
defmodule Hello.MixProject do
  use Mix.Project

  if Code.ensure_loaded?(MixPrecompiledDeps) do
    MixPrecompiledDeps.install(__MODULE__)
  end

  # project/0, deps/0, etc. as usual
end
```

**The manifest**, rendered by Nix:

```nix
manifest = pkgs.writeText "deps-manifest.exs" ''
  %{
    lock: %{sha256: "${builtins.hashFile "sha256" ./mix.lock}"},
    deps: %{
      "jason" => %{
        dest: "${jason}/src",
        build: "${jason}/lib/erlang/lib/jason-1.4.5",
        version: "1.4.5"
      }
    }
  }
'';
```

**The check**: set the manifest, put the SCM on `ERL_LIBS`, run `mix`:

```nix
pkgs.stdenv.mkDerivation {
  name = "hello-test";
  src = ./.;
  nativeBuildInputs = [ beamPackages.erlang beamPackages.elixir ];
  MIX_ENV = "test";
  MIX_PRECOMPILED_DEPS = manifest;

  buildPhase = ''
    export HOME=$TMPDIR
    export ERL_LIBS=${beamPackages.mixPrecompiledDeps}/lib/erlang/lib
    mix test
    touch $out
  '';
}
```

The SCM comes in on `ERL_LIBS` rather than as a project dependency because
it has to be loaded before Mix resolves dependencies.

## The Elixir patches

1. `Mix.Dep.load_paths/1` uses the dependency's `:build` path instead of
   assuming `_build/<env>/lib/<app>`.
2. `Mix.AppLoader` gets the same fix.
3. A `:precompiled` dependency option: Mix never recompiles such a
   dependency, and `mix deps.compile` raises a clear error instead of trying
   to rebuild it.

None of them change behavior for Mix's built-in SCMs. To apply them, and
package the SCM, extend your BEAM package set (the same thing `flake.nix`
does):

```nix
beamPackages = pkgs.beamPackages.extend (final: prev: {
  elixir = prev.elixir_1_20.overrideAttrs (old: {
    patches = (old.patches or [ ]) ++ [
      "${src}/patches/0001-Trust-dep-build-in-Mix.Dep.load_paths-1.patch"
      "${src}/patches/0002-Trust-dep-build-in-Mix.AppLoader.load_apps-5.patch"
      "${src}/patches/0003-Support-a-precompiled-option-on-dependencies.patch"
    ];
  });

  mixPrecompiledDeps = final.buildMix {
    name = "mix_precompiled_deps";
    version = "0.2.0";
    inherit src;
    beamDeps = [ ];
  };
});
```

## Reference

### Manifest

| Field | Meaning |
|---|---|
| `lock.sha256` | SHA-256 of `mix.lock`. If it doesn't match, `mix` fails before loading anything. Optional but recommended. |
| `dest` | The dependency's source tree (for resolution, `import_deps`, etc.) |
| `build` | Its compiled app directory, containing `ebin/` |
| `version` | Optional per-dependency version check, for manifests without `lock` |

Dependencies missing from the manifest are treated like unfetched Hex
dependencies: optional ones are dropped, required ones fail as "not
available". Dependencies with explicit `:path` or `:git` are left alone.

### Local dev shell

For a checkout where every plain `mix` command should use the store, pass a
directory instead of setting the variable:

```elixir
MixPrecompiledDeps.install(__MODULE__, manifest_dir: ".nix-deps")
```

The hook then loads `.nix-deps/deps-manifest-<env>.exs` when
`MIX_PRECOMPILED_DEPS` is unset. Symlink the manifests there (and add them
as GC roots). If `mix.lock` changes, every `mix` command fails until you
regenerate them.

### Errors

It's designed to fail loudly rather than quietly use a wrong build.

| Error | Meaning / fix |
|---|---|
| `MIX_PRECOMPILED_DEPS was built from a different mix.lock` | The manifest is stale. Rebuild it. |
| a dependency is "not available" | A required dependency is missing from the manifest. Rebuild it. |
| `cannot compile dependencies: ... precompiled and immutable` | A dependency's compile-time config (`compile_env`) no longer matches your project. Rebuild it with the right config. |
| `cannot checkout dependency ...` | Something ran `mix deps.get` with the manifest active. Unset `MIX_PRECOMPILED_DEPS` for Hex workflows. |
